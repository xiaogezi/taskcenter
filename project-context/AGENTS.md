# 项目上下文工作规则

## 项目上下文位置

项目长期上下文保存在 `project-context` 目录。

## 文件语言

所有项目上下文文档优先使用中文。

## 开始任务前

处理复杂任务前，应优先阅读：

1. `00-项目概览` - 项目基本信息
2. `50-当前状态` - 当前进度
3. 与任务相关的 `10-架构与设计`
4. 与任务相关的 `20-规范`
5. 与任务相关的 `30-决策`
6. 与任务相关的 `40-经验与问题`

不得无差别加载整个上下文库。

## 内容维护规则

1. 不得把模型推测保存为已确认事实。
2. 新决策、新经验、新规范建议默认写入 `90-Agent待审核`。
3. 不得直接覆盖正式架构、正式规范和已接受决策。
4. 不得永久删除上下文，废弃内容移动到 `99-归档`。
5. 发现冲突时，应同时保留冲突内容并生成说明。
6. 发现重复内容时，应提出合并建议，而不是自行删除。
7. 正式知识应尽量包含来源、背景或验证依据。
8. 文档必须优先保证人类阅读体验。

## Agent 可直接修改的内容

- `50-当前状态`
- `60-任务会话`
- `90-Agent待审核`

## Agent 需要提案后修改的内容

- `10-架构与设计`
- `20-规范`
- `30-决策`
- `40-经验与问题` 中的已确认内容

## 任务结束后

任务完成后，判断是否产生：

- 项目事实变化
- 当前状态变化
- 新决策
- 成功经验
- 失败经验
- Bug 经验
- 已知问题
- 规范修改建议

有长期价值的内容写入 `90-Agent待审核`。

不保存无价值的执行流水账。
