# 架构总览

## 一句话结论

ReqRadar 采用本地优先架构，通过同步脚本读取 Codex 会话，Next.js 前端展示看板，MCP Server 提供 Agent 任务协议。

## 背景

Codex 任务需求散落在会话中，难以追踪验收状态。需要本地工具提取、聚合和展示需求状态。

## 架构结构

## 模块职责

| 模块 | 职责 | 文件 |
|------|------|------|
| 前端看板 | 需求状态展示 | `app/page.tsx` |
| 同步脚本 | 读取 Codex 会话 | `scripts/sync-codex.mjs` |
| MCP Server | Agent 任务协议 | `scripts/reqradar-mcp.mjs` |
| 控制服务 | 本地 HTTP API | `scripts/control-server.mjs` |
| 任务账本 | 任务状态持久化 | `scripts/task-ledger.mjs` |
| 同步 Worker | 会话变化监听 | `scripts/reqradar-sync-worker.mjs` |

## 数据流

1. Codex 会话写入 `~/.codex/sessions/`
2. 同步脚本读取会话，提取需求
3. 需求数据写入 `data/dashboard.json`
4. 前端读取 JSON，渲染看板
5. Agent 通过 MCP 查询/更新任务状态
6. 任务事件写入 `data/task-events.jsonl`

## 关键边界

- Codex 会话只读，不修改
- 认证信息不读取
- 聊天内容不上传
- 任务状态持久化到本地

## 必须遵守的约束

- 所有 Codex 会话访问只读
- 不读取 auth.json、API Key
- 不上传聊天内容
- 任务验证基于证据，不接受 Agent 自称 verified

## 已知限制

- 无自动同步（需手动或定时）
- 无向量搜索
- 无多 Agent 并发支持
- 依赖 Codex 会话文件结构稳定
